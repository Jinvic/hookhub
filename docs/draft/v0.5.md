# HookHub 设计文档（草案 v0.5）

> **一句话定位**：HookHub 是一个可插件化扩展的 Webhook 中间件——从任意服务接收 Webhook，按规则解析、转换并转发到任意目标。
>
> *Receive webhooks from anywhere, route them anywhere.*

相对 [v0.4](v0.4.md)：以 **v0.7.0 主干实现**为准，补齐 AstrBot、Target 连通性探测、`formatTime` 等已落地能力；并**重新纳入可选 CEL `when`**（字段级过滤），范围严格限定在路由层。v0.4 及更早草案保留为历史，不再回改。

## 1. 背景与目标

### 1.1 问题

各类 SaaS / 自建服务推送原始 JSON Webhook，结构不一，直接进 IM 可读性差；常需扇出到多个目标。仅靠 `source` + `type` 无法表达「某项目 / 某优先级 / 某 nickname」等字段级规则，若写死在 Source 代码里则每次改条件都要发版。

### 1.2 目标

- 统一入口 `/hook/{name}` 多来源接入  
- 统一 `Event` → 配置化路由（含可选字段条件）→ `Message` → Target  
- 编译期插件（driver 注册），单二进制  
- 尽力投递、可观测；入站 dry-run 与出站连通性探测分离  
- 默认可运行一组常用 Source / Target；冷门出站用 `http` 逃生  

### 1.3 非目标（v0.5）

- Web UI、多租户、集群  
- 通用入站 Source（JSON 透传万能解析）  
- 运行时热插拔插件、双仓库插件市场  
- CEL 动态选 Target / 改 URL / 取代 `text/template`  
- 持久化队列、死信、跨进程去重（另立项）  
- Query 参数鉴权（ntfy `?auth=`）  
- `http` Target 的任意 body 模板 / Discord·Slack 专用 schema

## 2. 总体架构

```text
POST /hook/{name}
       │
       ▼
  Source 实例（map[name]）
  Verify → Parse → Event
  handler 写入 Event.Source = name
       │
       ├─ ?debug=1 → 日志预览，200，结束（无副作用）
       │
       ├─ 立即 200 ACK
       │
       └─ goroutine → Pipeline
              MatchingRoutes（source + type + when）
              对每个 Action：
                actions[].when？
                Template.Render({Event, Vars})
                Target.Send(ctx, msg)

POST /test/target/{name}   ← 管理面：同步 Send 测试 Message（有副作用）
GET  /healthz | /readyz    ← 存活 / 就绪（不探测外部 Target）
```

启动日志打印具体路由：`POST /hook/…`、`POST /test/target/…` 等。

**三层解耦**：Source → Event → Target。条件与模板在路由层；Target 只吃渲染后的 `Message`。

## 3. 核心数据模型

### 3.1 Event / Message

- `Event`：`ID/Source/Type/Time/Subject/Data/Raw/Headers`  
- `Message`：`Title/Body/Format/Priority/Extra`  
- `RenderContext`：`{ Event, Vars }`，`Vars` ← `sources[].vars`  
- 模板：`missingkey=error`；内置 `formatTime`（IANA 时区，默认布局 `2006-01-02 15:04`）  
- `vars.base_url`（深链）与 Target `config.url`（推送地址）**不是同一概念**

### 3.2 Route / Match / Action（含 when）

```go
type Route struct {
    Name    string
    Match   Match
    Actions []Action
}

type Match struct {
    Source string // 精确实例名；空 = 任意
    Type   string // '.' 分段通配，'*' = 恰好一段；空 = 任意
    When   string // 可选 CEL；空 = true
}

type Action struct {
    Target   string
    When     string // 可选 CEL；空 = true；用于扇出时按目标细控
    Template Template
}
```

**匹配顺序（单条 Route）**

1. `source` 精确（若配置）  
2. `type` 分段通配（若配置）  
3. `match.when` 求值须为 `true`  
4. 进入 Actions；每个 Action 再求 `actions[].when`，为 `true` 才 Render + Send

## 4. CEL `when`（v0.5 核心增量）

### 4.1 动机（真实配置场景）

| 场景 | 仅靠 `type` | 期望 |
| --- | --- | --- |
| Vikunja 提醒只推某 `project.id` / `task.priority` | 否 | `match.when` |
| Ech0 评论排除某 `nickname` | 否 | `match.when`（两 Target 共用）或 `actions[].when`（只挡一个） |

### 4.2 表达式环境

建议激活变量（名称锁定后写进实现与 README）：

| 变量 | 含义 |
| --- | --- |
| `source` | `Event.Source`（string） |
| `type` | `Event.Type`（string） |
| `subject` | `Event.Subject`（string） |
| `data` | `Event.Data`（`map[string]any`） |
| `vars` | 该 Source 实例的模板 Vars（`map[string]string`） |

示例：

```yaml
match:
  source: vikunja
  type: "task.reminder.*"
  when: 'data.project.id == 2'

match:
  source: ech0
  type: "comment.created"
  when: 'data.payload_raw.Comment.nickname != "bot"'
```

### 4.3 编译与求值策略

| 项 | 行为 |
| --- | --- |
| 依赖 | `github.com/google/cel-go` |
| 编译时机 | **加载配置时**编译全部非空 `when`；失败 → 进程拒绝启动 |
| 返回类型 | 必须是 bool |
| 运行时错误 | 打 Warn/Error，**跳过**该 Route 或 Action；不影响 HTTP ACK |
| 数字类型 | JSON → `map[string]any` 后数字多为 `float64`；文档说明，必要时在求值前规范化 |
| 性能 | 预编译 `cel.Program`；热路径只 `Eval` |

### 4.4 明确不做

- CEL 计算结果作为 `actions[].target`  
- CEL 改写 Target URL / UMO / topic  
- 在 ntfy / gotify / astrbot / http 的 `config` 里嵌 CEL  
- 用 CEL 替代 `text/template` 做正文渲染

## 5. 插件接口与驱动

```go
type Source interface {
    Driver() string
    Verify(req *http.Request, body []byte) error
    Parse(req *http.Request, body []byte) (*model.Event, error)
}

type Target interface {
    Driver() string
    Send(ctx context.Context, msg *model.Message) error
}
```

### 5.1 已实现驱动（v0.7.0）

| 角色 | driver | 要点 |
| --- | --- | --- |
| Source | `vikunja` | HMAC / none；提醒与逾期等 |
| Source | `ech0` | HMAC / none；`X-Ech0-*`；时间窗；topic 白名单 |
| Target | `ntfy` | Header 发布；none / basic / token；Extra 头白名单 |
| Target | `gotify` | `POST /message` + `X-Gotify-Key`；priority 0–10；extras |
| Target | `http` | 固定 URL；plain / json；鉴权；默认不跟随重定向（包名 `httpout`） |
| Target | `astrbot` | `POST /api/v1/im/messages`；Bearer；纯文本 `message` + 配置 `umo` |

### 5.2 扩展策略（同 v0.4）

主仓库加专用驱动为默认；出站字段不合先试 `http`；入站优先专用 Source；不拆插件仓、不做 `.so` 热加载。

## 6. 配置与 HTTP 面

见 [`config.example.yaml`](../../config.example.yaml)。

| 字段 | 含义 |
| --- | --- |
| `server.addr` / `log_level` | 监听与日志级别 |
| `sources[]` / `targets[]` | 实例名 + driver + config（+ source vars） |
| `routes[].match.source\|type\|when` | 粗筛 + 可选 CEL |
| `routes[].actions[].target\|when\|template` | 扇出；可选 per-action CEL |

### 6.1 HTTP 端点

| 端点 | 语义 |
| --- | --- |
| `POST /hook/{name}` | 业务入站；`{name}` = Source 实例名 |
| `POST /hook/{name}?debug=1` | 验签+解析+日志，**不**转发 |
| `POST /test/target/{name}` | 同步向 Target 实例发测试消息（**真实投递**）；可选 JSON `title`/`body` |
| `GET /healthz` / `GET /readyz` | 存活 / 就绪；**不**探测外部 Target |

`/test/target` 与 `/hook?debug=1` 对称：一个测出站连通，一个测入站解析。探测有副作用，故用 POST，且不并入 healthz。

### 6.2 `http` / AstrBot 约束摘要

- 出站 URL（及 AstrBot `umo`）**仅**来自配置  
- AstrBot：`message` 第一版为纯文本（title + body 拼接）

## 7. 处理流水线

```text
handleHook
  1. 取 Source；未知 → 404 + Warn
  2. 读 body（≤1MiB）
  3. Verify → 401；Parse → 400
  4. debug=1 → 预览日志，200
  5. 200 + Flush
  6. go Process
       MatchingRoutes(source, type, when)
       for action:
         action.when？
         Render → Send
         单 Action 失败只打日志，继续扇出

handleTestTarget
  1. 取 Target；未知 → 404
  2. 组装测试 Message（可 JSON 覆盖）
  3. 同步 Send（短超时）→ 200 / 502
```

| 项 | 行为 |
| --- | --- |
| 投递保证 | at-most-once（业务路径） |
| 去重 / 队列 / 重试 | 未实现 |
| Target 测试 | 同步；失败对操作者可见 |

## 9. 可靠性与安全

- Source 验签；Body 上限 1MiB  
- 模板无任意代码；CEL 沙箱且仅 bool  
- 出站固定 URL / 不跟随重定向（http）  
- `/test/target` 会发真消息：假定管理面网络边界；日后可统一管理鉴权  
- 日志：可配级别；错误路径不静默  

未做：持久化队列、Prometheus、管理面强制 Token。
