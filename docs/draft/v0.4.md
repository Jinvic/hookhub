# HookHub 设计文档（草案 v0.4）

> **一句话定位**：HookHub 是一个可插件化扩展的 Webhook 中间件——从任意服务接收 Webhook，按规则解析、转换并转发到任意目标。
>
> *Receive webhooks from anywhere, route them anywhere.*

相对 [v0.3](v0.3.md)：以 **v0.6.0 主干实现**为准，补齐已落地驱动与可观测性，并锁定扩展策略（编译期插件、不做通用入站、通用出站已具备）。v0.3 及更早草案保留为历史，不再回改。

---

## 0. 决策记录（相对 v0.3）

| 决策 | 取值 |
| --- | --- |
| 投递语义 | **at-most-once**（同 v0.3）：Verify/Parse 成功后立即 HTTP 200，再异步 `Process` |
| `Target.Send` | `Send(ctx, msg)`；**移除**未使用的 `cfg`（不再预留 Action 级覆盖） |
| 扩展方式 | **编译期注册** + 单二进制；主仓库内置默认可运行驱动 |
| 仓库拆分 | **暂不**拆「核心仓 / 插件仓」；Go 运行时 `.so` / 热加载 **不做** |
| 私有驱动 | 若需要：未来抽薄 SDK，用户自建 `main` 链接官方 + 私有驱动；非现在必做 |
| 通用入站 | **不做**；入站优先专用 Source |
| 通用出站 | **已做** `driver: http`（固定配置 URL，防 SSRF） |
| 可观测 | `server.log_level`；启动打印具体路由；HTTP 错误路径打 Warn |
| 发布 | `v*` 标签 → Docker Hub 多架构镜像 + GitHub Release 二进制；说明取自 CHANGELOG |

继承自 v0.3 且仍有效：Viper + ExpandEnv、`Driver()` / `driver`、路径=`sources[].name`、模板 `{ Event, Vars }`、分段 type 通配、无 CEL。

## 1. 背景与目标

### 1.1 问题

各类 SaaS / 自建服务推送原始 JSON Webhook，结构不一，直接进 IM 可读性差；常需扇出到多个目标。

### 1.2 目标

- 统一入口 `/hook/{name}` 多来源接入  
- 统一 `Event` → 配置化路由 → `Message` → Target  
- 编译期插件（driver 注册），单二进制  
- 尽力投递、可观测（结构化日志 + 可配级别）  
- 默认可运行一组常用 Source / Target；冷门出站用 `http` 逃生

### 1.3 非目标（v0.4）

- Web UI、多租户、集群  
- CEL / `when`  
- 持久化队列、死信、跨进程去重  
- 通用入站 Source（JSON 透传万能解析）  
- 运行时热插拔插件、双仓库插件市场  
- Query 参数鉴权（ntfy `?auth=`）  
- `http` Target 的任意 body 模板 / Discord·Slack 专用 schema（不合则专用 Target）

## 2. 总体架构

```text
POST /hook/{name}
       │
       ▼
  Source 实例（map[name]）
  Verify → Parse → Event
  handler 写入 Event.Source = name
       │
       ├─ ?debug=1 → 日志预览，200，结束
       │
       ├─ 立即 200 ACK
       │
       └─ goroutine → Pipeline
              MatchingRoutes
              Template.Render({Event, Vars})
              Target.Send(ctx, msg)
```

启动时日志带上具体路由列表，例如：`GET /healthz`、`GET /readyz`、`POST /hook/vikunja`、`POST /hook/ech0`。

**三层解耦**：Source → Event → Target。编排在 `app`，模型与模板在 `model`。

---

## 3. 核心数据模型

### 3.1 Event / Message / Route

与 v0.3 相同：

- `Event`：`ID/Source/Type/Time/Subject/Data/Raw/Headers`  
- `Message`：`Title/Body/Format/Priority/Extra`  
- `Match`：`source` 精确 + `type` 按 `.` 分段通配（`*` = 一段）  
- `RenderContext`：`{ Event, Vars }`，`Vars` ← `sources[].vars`

### 3.2 模板约定

- `missingkey=error`：缺键仅使该 Action 失败，扇出继续  
- Source `vars.base_url` 用于深链；与 Target `config.url`（推送服务地址）**不是同一概念**，勿强行同名对齐

## 4. 插件接口

```go
type Source interface {
    Driver() string
    Verify(req *http.Request, body []byte) error
    Parse(req *http.Request, body []byte) (*model.Event, error)
}

type Target interface {
    Driver() string
    Send(ctx context.Context, msg *model.Message) error
}
```

- 装配时校验 `impl.Driver() == config.driver`  
- 注册方式：`internal/app` 内 `switch` 编译期装配（当前实现）

### 4.1 已实现驱动（v0.6.0）

| 角色 | driver | 要点 |
| --- | --- | --- |
| Source | `vikunja` | HMAC / none；提醒与逾期等 |
| Source | `ech0` | HMAC / none；`X-Ech0-*`；时间窗；topic 白名单 |
| Target | `ntfy` | Header 发布；none / basic / token；Extra 头白名单 |
| Target | `gotify` | `POST /message` + `X-Gotify-Key`；priority 0–10；extras |
| Target | `http` | 固定 URL；plain / json；none / bearer / basic / header；默认不跟随重定向 |

包名注意：`http` 驱动实现位于 `internal/target/httpout`，避免与 `net/http` 冲突；配置里仍写 `driver: http`。

### 4.2 扩展策略（锁定）

| 做法 | 态度 |
| --- | --- |
| 主仓库继续加专用 Source / Target | **默认** |
| 出站字段不合专用 IM | 先试 `http`；不够再专用 Target 或日后 body 模板 |
| 新入站需求 | **专用 Source**，不做 generic inbound |
| 用户私有驱动且不想 PR | 远期：导出接口 + 自编译二进制；**现在不拆仓** |
| Go `plugin` / gRPC 热加载 | **不做** |

## 5. 配置

见 [`config.example.yaml`](../../config.example.yaml)。

| 字段 | 含义 |
| --- | --- |
| `server.addr` | 监听地址 |
| `server.log_level` | `debug` / `info` / `warn` / `error`（默认 info） |
| `sources[].name` | 实例 → URL / `Event.Source` / `match.source` |
| `sources[].driver` | 插件 id |
| `sources[].vars` | 模板 `.Vars` |
| `sources[].config` | driver 专属 |
| `targets[].name` | `actions[].target` 引用 |
| `targets[].driver` / `config` | 插件与专属配置 |
| `routes` | match + template + 扇出 |

密钥：`${ENV}`，加载时 ExpandEnv；`config.yaml` gitignore。

### 5.1 `http` Target 约束

- URL **仅**来自配置，禁止由 Event / 模板改写（SSRF）  
- `body_format: json` 为固定字段 `{title,message,priority,format,extra}`，非 Discord/Slack Incoming 专用 schema  
- 默认 Client 不跟随重定向

## 6. 处理流水线

```text
handleHook
  1. 按 name 取 Source；未知 → 404 + Warn
  2. 读 body（≤1MiB）；失败 / 过大 → 4xx + Warn
  3. Verify → 401 + Warn
  4. Parse → 400 + Warn；写入 Source/Time/Headers
  5. debug=1 → 截断预览日志，200，返回
  6. 200 + Flush
  7. go Process(timeout=30s)
       MatchingRoutes → Render → Send
       单 Action 失败只打日志，继续扇出
```

| 项 | 行为 |
| --- | --- |
| 投递保证 | at-most-once |
| 去重 / 队列 / 重试 | 未实现 |
| debug | 不转发；body 日志有长度上限 |

## 8. 可靠性与安全（当前）

- Source 验签：Vikunja / Ech0 的 HMAC 或 none；Ech0 另有时间窗  
- Body 上限 1MiB  
- `text/template` 无任意代码执行  
- ntfy Extra 头白名单；gotify extras 命名空间映射  
- `http` Target：固定 URL + 不跟随重定向  
- 日志：可配级别；错误路径不静默；debug body 截断  

未做：持久化队列、Prometheus、内网 IP 拒绝列表（依赖「URL 仅来自配置」）。

## 11. 后续方向（优先级参考）

1. **按实际在用的上游加专用 Source**（如 Gitea、Uptime Kuma）——优于通用入站  
2. **按需专用 Target**（Telegram 等）；字段能靠 `http` 覆盖则不加  
3. 内存有界队列 + 有限重试 + LRU 去重（改变投递语义前需单独立项）  
4. 模板预编译、Prometheus  
5. 仅当出现真实的外部作者需求时：抽薄可导入 SDK；再评估是否拆 contrib 仓  

明确推迟：通用入站、CEL、Web UI、运行时插件。
